# ui-blind-compare

対象UIを有名作品の見た目へ寄せるためではなく、製品品質の差を先入観なしで特定するための手順です。

## 準備

1. 対象UIと、同じ目的・同じ入力方式・近い情報量を持つ本物UIを1枚以上ずつ用意します。`ui_capture` の生成物か `knowledge/ui-references/` の手動配置画像を使います。
2. 解像度とトリミング範囲を揃え、ゲーム名、ロゴ、ストア名、ファイル名など出自を示す情報を隠します。内容を有利に見せる加工は禁止です。
3. 画像を無作為に A / B（3枚以上なら A / B / C）へ割り当て、対応表は評価者から隠して匿名化します。

## 開示前評価

評価者は次の軸を各1〜5で採点し、スクリーンショット上の具体的位置と理由を記録します。

- 3秒以内に主要行動が分かるか
- 情報階層と視線誘導
- 文字の可読性、余白、密度
- 通常・hover・focus・disabled・loading・error の状態表現
- 操作に対する即時フィードバック
- コンポーネント、色、角丸、影、motion の一貫性
- 「出荷済み製品」に見える完成度

どちらが対象かを推測してもよいですが、正解を明かす前に採点、順位、改善指示を Markdown へ書き出して固定します。固定後の無断修正は禁止です。

## 開示と解釈

対応表を開示し、対象UIが負けた軸だけを修正候補へ変換します。本物UIのブランド固有表現をコピーせず、「階層」「間隔」「状態」「フィードバック」など再利用可能な原則へ翻訳します。対象UIが勝った軸も保存し、変更で失わない制約にします。

画像不足、比較目的の不一致、匿名化不能がある場合は勝敗を確定せず「根拠不足」とします。再キャプチャ条件または必要な手動画像を指定して停止してください。
